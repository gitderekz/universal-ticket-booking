CLIENT WORKFLOW ARCHITECTURE - COMPLETE SYSTEM FLOW
From Registration to Logout - Enumerated List Summary
PART ONE: ACCOUNT CREATION AND ONBOARDING
1.0 Initial Registration Process

1.1 The client navigates to the platform homepage and clicks the Sign Up button located in the top right corner of the navigation bar.

1.2 The system displays a registration form with two sections: personal information and account credentials.

1.3 In the personal information section, the client enters their full legal first name, full legal last name, a valid email address that has not been previously registered, a mobile phone number including the country code for Tanzania which is +255 followed by nine digits, and optionally selects their preferred language from the eight available options.

1.4 In the account credentials section, the client creates a username that must be unique across the platform, enters a password that meets the security requirements of at least eight characters with one uppercase letter, one lowercase letter, one number, and one special character, then confirms the password by typing it again exactly.

1.5 The client selects their preferred currency for displaying prices from the dropdown containing all active currencies, with TZS as the default.

1.6 The client checks two checkbox agreements confirming they accept the terms of service and privacy policy, and optionally checks a third box to receive promotional notifications.

1.7 After completing all fields, the client clicks the Register button.

1.8 The system validates all input fields, ensuring email format is correct, phone number has the proper number of digits, password meets complexity requirements, and the email is not already in use by another account.

1.9 Upon successful validation, the system hashes the password using bcrypt with twelve salt rounds and creates a new user record in the users table with role set to Customer, status set to pending email verification, preferred language and currency saved.

1.10 The system generates a unique email verification token and sends a verification link to the provided email address.

1.11 The client receives the email and clicks the verification link, which sets the email verified timestamp in their user record and changes account status to active.

1.12 The system redirects the client to the login page with a success message indicating their account is now active and they can log in.

1.1 First Login and Dashboard Overview

1.13 The client navigates to the login page and enters their email address and password.

1.14 The system validates the credentials and upon successful authentication generates a JSON Web Token access token that expires in fifteen minutes and a refresh token that expires in seven days.

1.15 The access token is stored in memory, while the refresh token is set as an HTTP-only cookie.

1.16 The client is redirected to their personalized customer dashboard.

1.17 The dashboard displays a welcome message showing the client's first name, a profile completion提示 if any information is missing, and a quick action bar with buttons for Book Transport, Book Facility, My Tickets, and Help.

1.18 The dashboard contains several sections: Statistics Cards showing total trips taken, upcoming bookings count, total amount spent, and active tickets count. Recently Viewed section showing the last three transports or facilities the client viewed. Popular Now section showing trending journeys and activities based on recent bookings. Recommended For You section showing personalized recommendations based on the client's booking history.

1.19 A notification bell icon in the navigation bar shows a badge with the number of unread notifications. When clicked, a dropdown displays the five most recent notifications with a link to view all.

1.20 A language switcher allows the client to change the interface language instantly between English, Swahili, Chinese, Russian, Spanish, French, German, and Portuguese.

1.21 A currency switcher allows the client to change the display currency, and all prices on the page automatically convert using the latest exchange rates.

1.22 A theme toggle button switches between light mode and dark mode, with the preference saved for future sessions.

PART TWO: SEARCH AND DISCOVERY
2.0 Searching for Transport Options

2.1 From the dashboard, the client clicks the Book Transport button in the quick action bar, or selects Transport from the main navigation menu.

2.2 The system displays the transport search page with a prominent search form at the top and popular routes displayed below.

2.3 The search form contains fields for origin city or station, destination city or station, departure date, and number of passengers with options for adults, children, and infants.

2.4 The client starts typing the origin location, and the system shows autocomplete suggestions from the stations table, displaying both station name and city.

2.5 The client selects the origin station from the suggestions, then similarly selects the destination station.

2.6 The client selects a departure date from a calendar picker that highlights dates with available journeys. Dates with no available services are grayed out and cannot be selected.

2.7 The client selects the number of passengers using plus and minus buttons for adults, children between ages three and twelve, and infants below age three.

2.8 The client clicks the Search button to begin the search.

2.9 The system queries the journeys table for journeys on the selected date where the departure time is in the future, the status is scheduled, and available seats count is greater than zero.

2.10 The system also checks for journeys on nearby dates if the selected date has no results and suggests alternative dates.

2.11 The search results page displays a list of available journeys matching the criteria.

2.12 Each search result card shows the transport name and type, departure time and arrival time, journey duration, origin and destination station names, available seats count indicated by a color-coded badge, ticket price per passenger, and a Select button.

2.13 The client can filter results by departure time range, price range, transport type, amenities, and departure station using sidebar filters.

2.14 The client can sort results by earliest departure, latest departure, cheapest price, shortest duration, or most available seats.

2.15 The client clicks the Select button on their preferred journey to proceed to the booking process.

2.1 Searching for Facility Options

2.16 From the dashboard, the client clicks the Book Facility button or selects Facilities from the main navigation menu.

2.17 The system displays the facility search page with search form fields for facility type, location, date, and number of people.

2.18 The client selects a facility category from Entertainment, Events, Outdoor, Housing, or Sports, then selects a specific facility type like Movie Theatre, Restaurant, or Hotel Room.

2.19 The client enters a location or uses the current location button to auto-detect nearby facilities.

2.20 The client selects a date from the calendar picker and the number of people or rooms needed.

2.21 The client clicks the Search button.

2.22 The search results show facility cards with name, type, location on a map, rating from reviews, base price, available slots or rooms, and a View Details button.

2.23 The client clicks View Details on a facility to see full information including photos, amenities, reviews, and available activities.

2.2 Viewing Facility Details

2.24 The facility detail page displays a hero image gallery with multiple facility photos, basic information including name, type, location, and average rating.

2.25 A calendar shows available dates for the next thirty days with color coding for fully booked days, partially available days, and fully available days.

2.26 Below the calendar, a list of activities available at this facility is displayed, each with name, description, duration, base price, and a Book Now button.

2.27 For movie theatres, the activities list shows current and upcoming movies with showtimes.

2.28 For hotels, the activities list shows room types with different prices, bed configurations, and availability.

2.29 For restaurants, the activities list shows dining sessions like lunch or dinner with table types.

2.30 The client reviews the facility information, reads customer reviews with ratings and comments, and checks the location on the embedded map.

2.31 The client clicks the Book Now button on their chosen activity to proceed to booking.

PART THREE: TRANSPORT BOOKING FLOW
3.0 Step One - Route and Station Selection

3.1 After selecting a journey from search results, the client is taken to the booking page with a six-step progress indicator at the top showing Step 1 of 6: Select Route and Stations.

3.2 The page displays a summary of the selected journey including transport name, departure date, and number of passengers.

3.3 A route diagram shows the full route from origin to destination with all intermediate stations marked as dots on a line.

3.4 The client sees two dropdown selectors: Boarding Station and Alighting Station.

3.5 The Boarding Station dropdown is pre-filled with the origin station from the search, but the client can change it to any station along the route where they want to board.

3.6 The Alighting Station dropdown is pre-filled with the destination station from the search, but the client can change it to any station before the final destination where they want to get off.

3.7 When the client changes the boarding station to a station that is not the route origin, the system automatically detects this and searches for a sub-route that starts at that station.

3.8 If a sub-route exists, the system displays a message: "A direct route from [boarding station] to [alighting station] has been found. Price adjusted to [new price]." The route diagram updates to show only the sub-route segment.

3.9 If no sub-route exists, the system calculates a partial price based on the difference between the alighting station cumulative price and the boarding station cumulative price, and displays a message: "Partial route price calculated: [calculated price]."

3.10 The system shows the price breakdown: original full route price, deduction for starting later, and final price per passenger multiplied by number of passengers.

3.11 The client clicks Confirm Selection to proceed to the next step.

3.1 Step Two - Date and Time Confirmation

3.12 The client moves to Step 2: Confirm Date and Time.

3.13 The system displays a calendar view showing the selected date highlighted, with other available dates around it in case the client wants to change.

3.14 Below the calendar, a timeline shows the departure time and arrival time in both standard format and Swahili time format if Swahili language is selected.

3.15 For Swahili time display, a 10:00 AM departure is shown as "4:00 asubuhi" and 2:00 PM arrival is shown as "8:00 mchana".

3.16 The system shows the duration of the journey in hours and minutes.

3.17 The client can click the Change Date button to select a different date, which will refresh the available journeys for that date.

3.18 The client clicks Continue to proceed.

3.2 Step Three - Seat Selection with Real-time Updates

3.19 The client moves to Step 3: Select Your Seats.

3.20 The system loads the seat map for the selected journey by fetching the seat layout from the seat_layouts table and the current seat status from seats, bookings, and seat_holds tables.

3.21 The seat map is displayed as a grid with the front of the vehicle at the top and back at the bottom.

3.22 A legend explains the color coding: Dark Blue for available seats, Red for already booked seats, Gray for seats held by other users, Orange for seats the current user has selected, Yellow for driver or operator seats which are not bookable, and Green for wheelchair accessible seats.

3.23 The client clicks on an available dark blue seat to select it. The seat turns orange immediately in the client's view.

3.24 The system sends a socket.io event to the server requesting a hold on that seat.

3.25 The server checks if the seat is still available, creates a seat_hold record with a ten-minute expiration, and broadcasts a seat-held event to all other clients viewing the same journey.

3.26 Other clients see that seat turn gray immediately, preventing them from selecting the same seat.

3.27 A countdown timer appears at the top of the seat map showing "Your seats are held for: 9:59 remaining".

3.28 The client continues selecting additional seats up to the number of passengers specified.

3.29 For each seat selected, the seat code appears in a "Your Selected Seats" list below the seat map.

3.30 If the client clicks an already selected orange seat, the system releases the hold, sends a seat-released event to the server, the server deletes the hold record, broadcasts to other clients that the seat is now available, and the seat returns to dark blue.

3.31 A message displays "Selected seats: [seat codes]" and the running total price updates.

3.32 The client clicks Continue when all seats are selected.

3.3 Step Four - Passenger Information

3.33 The client moves to Step 4: Passenger Details.

3.34 The system displays a form section for each selected seat, with the seat code displayed as a header.

3.35 For each passenger, the client enters: Full Name as it appears on identification, Age Category from Adult, Child, or Infant, Gender, and optional Identification Number if required for the journey.

3.36 For child and infant passengers, the system asks for date of birth to verify age eligibility.

3.37 A "Copy from account" button prefills the form with the client's own information for the first passenger.

3.38 Below the passenger forms, a Contact Information section asks for the primary contact person's full name, phone number, and email address for journey notifications.

3.39 The client can optionally check a box to receive SMS notifications for journey updates.

3.40 The client clicks Continue after validating all required fields are filled.

3.4 Step Five - Review Booking

3.41 The client moves to Step 5: Review Your Booking.

3.42 The system displays a comprehensive summary page divided into sections.

3.43 The Journey Summary section shows the transport name and type, route from origin to destination or sub-route if applicable, boarding station, alighting station, departure date and time in both standard and Swahili format, arrival time, and duration.

3.44 The Seat Summary section lists each selected seat code with the passenger name assigned to it and the price per seat.

3.45 The Passenger Summary section lists all passengers with their names, age categories, and any special requirements.

3.46 The Price Summary section shows the subtotal, any applicable taxes or fees, discounts if promo code applied, and the total amount payable in the client's selected currency.

3.47 A promo code field allows the client to enter a discount code and click Apply to see the discount reflected immediately.

3.48 The cancellation policy is displayed, showing refund eligibility windows and percentages.

3.49 A checkbox requires the client to confirm they have read and agreed to the booking terms and conditions.

3.50 The client clicks Proceed to Payment.

3.5 Step Six - Payment Processing

3.51 The client moves to Step 6: Payment.

3.52 The system displays a new countdown timer: "Complete payment within 4:59 before your seats are released."

3.53 The payment method selection shows available options categorized as Mobile Money, Bank Transfer, and Card Payment.

3.54 Mobile Money options include Airtel Money, M-Pesa, HaloPesa, and Yas Cash depending on the client's country.

3.55 Bank options include NBC Bank, NMB Bank, and CRDB Bank.

3.56 Card options include Visa and Mastercard.

3.57 The client selects a payment method, and the system expands a form specific to that method.

3.58 For mobile money, the client enters their mobile phone number registered with the mobile money service and clicks Pay Now. A confirmation prompt appears on their phone to enter their PIN.

3.59 For card payment, a secure iframe or redirect to a payment gateway collects card number, expiry date, CVV, and cardholder name. The system never stores card details directly.

3.60 The system processes the payment through the integrated payment gateway with the amount in TZS.

3.61 A loading spinner appears with the message "Processing payment, please wait..."

3.62 If the payment is successful, the system updates the booking status from holding to confirmed, converts all seat holds to permanent bookings by updating their status to converted, creates a payment record with status completed, generates a ticket with a unique QR code, sends a confirmation email to the client, and creates an in-app notification.

3.63 If the payment fails, the system displays an error message with the reason, allows the client to retry with the same method or select a different method, and the seat holds remain active for the remaining time.

3.64 If the payment timer expires before completion, the system automatically releases all seat holds, changes the booking status to expired, and displays a message: "Your seat hold has expired. Please start over to book these seats."

3.6 Receipt and Ticket Generation

3.65 After successful payment, the system redirects the client to the Booking Confirmation page.

3.66 A success animation plays with a green checkmark and the message "Booking Confirmed! Your ticket is ready."

3.67 The booking confirmation page displays a digital ticket card with a prominent QR code at the center.

3.68 Below the QR code, the ticket details show: booking reference number formatted like BKG-20260505-X7K9, ticket code for validation, passenger names and seat assignments, journey details with departure and arrival times, and the total amount paid.

3.69 Two buttons are prominently displayed: Download PDF Receipt and View All Tickets.

3.70 The client clicks Download PDF Receipt, and the system generates a PDF document containing the full receipt with company logo, booking details, payment summary, and terms and conditions, then triggers the browser download.

3.71 The client can also click Add to Apple Wallet or Add to Google Wallet if supported for digital ticket storage.

3.72 The system automatically sends an email to the client's registered email address containing the booking confirmation and a link to download the receipt.

3.73 A text message is sent to the client's phone with the booking reference and a link to view the ticket online.

3.74 The client clicks View All Tickets to see their complete ticket history.

PART FOUR: FACILITY BOOKING FLOW
4.0 Step One - Activity and Date Selection

4.1 After clicking Book Now on a facility activity, the client is taken to the facility booking page with a progress indicator.

4.2 The page displays the facility name, activity name, and a summary of the booking.

4.3 The client selects a date from a calendar showing available dates for this activity. Unavailable dates are crossed out.

4.4 A time slot selector displays all available start times for the selected date, showing the time in both standard and Swahili format if applicable.

4.5 The client selects a time slot, and the system shows the duration of the activity and the end time.

4.6 The client selects the number of participants or units needed using plus and minus buttons.

4.7 For seat-based facilities like theatres, the system displays the number of seats selected.

4.8 For unit-based facilities like hotels, the system displays the number of rooms or tables selected.

4.9 The client clicks Continue to proceed.

4.1 Step Two - Seat or Unit Selection

4.10 For seat-based facilities, the client moves to a seat map similar to transport but without driver seats.

4.11 The seat map shows the theatre or stadium layout with rows and seats, color coded for available, booked, and held.

4.12 The client selects seats following the same hold mechanism as transport, with a ten-minute hold timer and real-time socket updates.

4.13 For unit-based facilities like hotels, the system displays a list or grid of available units.

4.14 Each hotel room card shows the room number, room type like Standard or Suite, bed configuration like King or Twin, view type like City View or Ocean View, amenities specific to that room, and price per night.

4.15 The client selects a room by clicking the Select button on the room card.

4.16 For multiple rooms, the client repeats the selection process, and selected rooms appear in a sidebar.

4.17 For parking lots, the system displays a map or numbered list of parking spots, distinguishing between covered and uncovered, EV charging available, and handicap accessible.

4.18 The client selects the desired parking spot or allows the system to assign the best available spot automatically.

4.19 For restaurants, the system displays a table layout diagram showing table sizes, indoor or outdoor location, and any special features like window view or private area.

4.20 The client selects their preferred table from the diagram.

4.21 After selecting all seats or units, the client clicks Continue.

4.2 Step Three - Passenger or Guest Information

4.22 The client enters names and contact information for the booking.

4.23 For events, each ticket requires a guest name.

4.24 For hotel bookings, the client enters the primary guest name, check-in time preference, and any special requests like extra pillows or late checkout.

4.25 For restaurant bookings, the client enters the name the reservation is under, any dietary restrictions or allergies, and special occasion notes like birthday or anniversary.

4.26 The client provides a contact phone number for booking confirmations and waitlist notifications.

4.27 The client clicks Continue.

4.3 Step Four - Review and Payment

4.28 The review page shows the facility name and activity details, selected date and time, selected seats or rooms with individual prices, subtotal and total amount, and cancellation policy.

4.29 The client confirms all details and clicks Proceed to Payment.

4.30 The payment process follows the same steps as transport booking, with the same timer, payment method options, and confirmation flow.

4.31 After successful payment, the client receives a digital ticket with a QR code for activity or event entry.

4.32 For hotel bookings, the ticket serves as a booking confirmation that can be presented at check-in.

4.33 For restaurant bookings, the ticket shows the reservation time and table number.

PART FIVE: TICKET MANAGEMENT
5.0 Viewing All Tickets

5.1 The client clicks My Tickets in the navigation menu or dashboard.

5.2 The system displays two tabs: Upcoming Tickets and Past Tickets.

5.3 The Upcoming Tickets tab shows all confirmed bookings with future departure dates or activity dates.

5.4 Each ticket card displays the booking reference, transport or facility name, date and time, seat or room number, and a QR code thumbnail.

5.5 A View Full Ticket button opens the detailed ticket view.

5.6 The Past Tickets tab shows completed journeys and activities with options to rebook or leave a review.

5.1 Detailed Ticket View

5.7 The client clicks on a ticket to view the full details.

5.8 The ticket detail page displays a large QR code at the top that can be scanned for entry.

5.9 Below the QR code, essential information is prominently displayed: transport name, departure date and time, boarding station, seat number, passenger name.

5.10 Additional details include arrival time, alighting station, duration, and any special instructions.

5.11 A map shows the boarding station location with directions.

5.12 For facility tickets, the QR code is displayed along with the activity name, start time, seat or table number, and venue address.

5.13 A Download PDF button allows the client to save or print the ticket.

5.14 An Add to Calendar button adds the event to the client's device calendar.

5.15 A Share Ticket button generates a link to share the ticket with another person.

5.16 For upcoming tickets, a Cancel Booking button is available within the cancellation window.

5.2 Ticket Validation and Check-in

5.17 On the day of the journey, the client opens their ticket in the app or prints the PDF.

5.18 At the boarding gate or venue entrance, staff scans the QR code using a scanner device or mobile app.

5.19 The staff sees the booking details and marks the ticket as validated.

5.20 The client receives a notification that their ticket has been scanned and validated.

5.21 For group bookings, each passenger may have their own individual ticket with separate QR codes.

5.22 The client can show their phone screen with the QR code, and the scanner reads it directly.

5.23 The system prevents re-use of the same ticket by marking it as used after first validation.

5.24 If the client loses their ticket, they can log in to their account, go to My Tickets, and regenerate the PDF or display the QR code again.

5.3 Ticket Sharing and Transfer

5.25 The client clicks Share Ticket on the ticket detail page.

5.26 The system provides options to share via WhatsApp, email, or generate a shareable link.

5.27 The shareable link opens a web page displaying the ticket QR code without requiring login.

5.28 The link expires after a configurable time, typically twenty-four hours before departure.

5.29 For ticket transfer to another person, the client clicks Transfer Ticket.

5.30 The client enters the recipient's email address and a transfer reason.

5.31 The system sends an email to the recipient with a link to accept the ticket transfer.

5.32 When the recipient accepts, the ticket is reassigned to their account, and the original client loses access to the ticket.

5.33 A transfer fee may apply depending on the company's policy.

6.3 Status badges show Confirmed in green, Completed in blue, Cancelled in red, Pending in yellow, or Expired in gray.

6.4 The client can filter bookings by status, date range, and type using dropdown filters.

6.5 The client can search for a specific booking using the booking reference.

6.6 Each row has a View Details button that opens the full booking details page.

6.7 The booking detail page shows the complete information about the booking.

6.8 The top section displays the booking reference, status, booking date, and the company name.

6.9 The journey or activity details section shows route, stations, date, time, duration, and transport or facility name.

6.10 The seat or unit section lists each seat or room with its code, assigned passenger name, and price.

6.11 The passenger section lists all passengers with names, age categories, and contact information.

6.12 The payment section shows the amount paid, payment method, payment date, and transaction reference.

6.13 An Invoice button downloads a detailed invoice suitable for reimbursement or accounting.

6.14 A View Ticket button navigates to the ticket detail page.

6.15 A Cancel Booking button is displayed if the booking is still within the cancellation window.

6.2 Booking Cancellation

6.16 The client clicks Cancel Booking on the booking detail page.

6.17 The system displays a cancellation confirmation dialog showing the cancellation policy applicable to this booking.

6.18 The cancellation policy states: "If cancelled more than 24 hours before departure, 100% refund. If cancelled 12-24 hours before, 50% refund. If cancelled less than 12 hours before, no refund."

6.19 The system calculates and displays the refund amount based on the current time and departure time.

6.20 The client selects a cancellation reason from a dropdown: Change of Plans, Found Better Option, Emergency, Incorrect Booking, or Other.

6.25 The refund typically takes three to seven business days to appear in the client's account depending on the payment method.

6.26 The client can view the cancellation status and refund amount on the booking detail page.

6.3 Rebooking a Past Booking

6.27 From the Past Tickets tab or Past Bookings filter, the client clicks Rebook on a past booking.

6.28 The system pre-fills the search form with the same origin, destination, passenger count, and approximately the same date.

6.29 The client adjusts the date if needed and clicks Search.

6.30 The search results show available journeys, and the client selects one to start a new booking with the passenger information pre-filled from the past booking.

6.31 The client can modify any details before completing the new booking.

PART SEVEN: NOTIFICATIONS AND COMMUNICATIONS
7.0 Types of Notifications

7.1 The client receives notifications through three channels: in-app notification center, email, and SMS for critical alerts.

7.2 Booking Confirmation notifications arrive immediately after successful payment, containing the booking reference, summary of details, and a link to view the ticket.

7.3 Payment Receipt notifications include the transaction reference, amount paid, payment method, and a link to download the PDF receipt.

7.4 Journey Reminder notifications are sent 24 hours before departure, 2 hours before departure, and 30 minutes before departure, containing the departure time, boarding station, seat number, and a link to view the ticket.

7.5 Delay Notifications are sent when the company updates a journey status to delayed, containing the original departure time, new departure time, and delay reason.

7.6 Cancellation Notifications are sent when a company cancels a journey, containing cancellation reason and refund information.

7.7 Seat Hold Expiring notifications are sent 2 minutes before the ten-minute hold expires, reminding the client to complete their booking.

7.8 Promotional notifications are sent when there are special offers, discounts, or new routes relevant to the client.

7.1 Notification Center

7.9 The client clicks the bell icon in the navigation bar to open the notification dropdown.

7.10 The dropdown shows the ten most recent notifications with the newest at the top, each showing the notification type icon, title, message preview, and time ago.

7.11 Unread notifications have a blue dot next to them.

7.12 The client clicks a notification to navigate to the relevant page: booking confirmation goes to booking detail, reminder goes to ticket, promotion goes to search page with filter applied.

7.13 Clicking See All Notifications opens the full notification center page.

7.14 The notification center page shows all notifications paginated, grouped by date: Today, Yesterday, This Week, Earlier.

7.15 Each notification has a Mark as Read button and a Delete button.

7.16 A Mark All as Read button at the top marks all unread notifications as read.

7.17 The client can filter notifications by type using a dropdown filter.

7.18 Notification preferences can be accessed from the profile settings page, allowing the client to opt out of promotional notifications or choose to receive email digests instead of individual emails.

7.2 Communication with Companies

7.19 On the booking detail page, the client clicks Contact Support.

7.20 The system displays a contact form with the client's email and booking reference pre-filled.

7.21 The client selects a subject from Inquiry, Complaint, Change Request, or Other.

7.22 The client writes their message in a text area and can optionally attach images.

7.23 The client clicks Send Message.

7.24 The system creates a support ticket linked to the booking and sends an email to the company's support email address.

7.25 The client receives an auto-reply acknowledging receipt of their message.

7.26 The client can view the status of their support request from the Help Center page.

7.27 When the company replies, the client receives a notification and can view the response in the notification center.

PART EIGHT: PROFILE AND SETTINGS MANAGEMENT
8.0 Profile Management

8.1 The client clicks on their avatar in the top right corner and selects Profile from the dropdown menu.

8.2 The system displays the profile page with sections for Personal Information, Account Security, Notification Preferences, and Language & Region.

8.3 In the Personal Information section, the client can update their first name, last name, email address, phone number, and upload a new profile photo.

8.4 Any change to email address requires reverification by clicking a link sent to the new email address.

8.5 In the Account Security section, the client can change their password by entering the current password, new password with confirmation, and clicking Update Password.

8.6 The client can enable two-factor authentication, which requires scanning a QR code with an authenticator app like Google Authenticator and entering a verification code.

8.7 Once enabled, the client will need to enter a six-digit code from the authenticator app after entering their password on each login.

8.8 Backup codes are provided for the client to save in a secure place in case they lose access to their authenticator app.

8.1 Notification Preferences

8.9 In the Notification Preferences section, the client can configure which notifications they receive and through which channels.

8.10 For each notification type, there are checkboxes for In-app, Email, and SMS where applicable.

8.11 Booking Confirmation notifications default to all three channels checked. The client can uncheck any channel.

8.12 Promotional notifications are opt-in only, defaulting to unchecked.

8.13 The client can set a quiet hours schedule, where notifications are silenced between specified times, except for critical alerts like journey delays.

8.14 Email digest frequency can be set to Never, Daily, or Weekly, which sends a summary of notifications instead of individual emails.

8.15 The client clicks Save Preferences to apply the changes.

8.2 Language and Region Settings

8.16 In the Language & Region section, the client selects their preferred language from the eight available options.

8.17 When the client changes the language, the entire interface switches immediately to demonstrate the change before saving.

8.18 The client selects their preferred time zone from a dropdown of global time zones, with East Africa Time as the default.

8.19 The client selects their preferred display currency from the dropdown of active currencies with exchange rates.

8.20 All prices on the page automatically convert to the selected currency using the latest exchange rates from the currencies table.

8.21 The client can choose date format from DD/MM/YYYY, MM/DD/YYYY, or YYYY-MM-DD.

8.22 The client can choose time format from 12-hour or 24-hour.

8.23 The client clicks Save Preferences to apply the changes.

8.3 Address Book Management

8.24 From the profile page, the client clicks Address Book in the sidebar.

8.25 The system displays a list of saved addresses for the client.

8.26 The client clicks Add New Address.

8.27 A form appears with fields for address label like Home or Work, street address, city, state or region, postal code, country, and special delivery instructions.

8.28 The client can set an address as the default for billing or default for contact.

8.29 The client clicks Save Address.

8.30 Saved addresses can be edited or deleted from the address book.

8.31 During booking, the client can select an address from their address book instead of typing it each time.

8.4 Payment Methods Management

8.32 From the profile page, the client clicks Payment Methods in the sidebar.

8.33 The system displays saved payment methods if any exist.

8.34 The client clicks Add Payment Method.

8.35 A secure form appears asking for card number, expiry date, CVV, and cardholder name, processed through a PCI-compliant payment gateway.

8.36 The system does not store full card numbers but stores a token representing the card and the last four digits for display.

8.37 The client can set a payment method as default for faster checkout.

8.38 For mobile money, the client can save their registered mobile number for quick selection.

8.39 Saved payment methods can be deleted, but the client must have at least one active payment method if they want to enable one-click booking.

8.40 The client can enable One-Click Booking, which skips the payment step for future bookings under a certain amount, using the default payment method automatically.

9.0 Leaving a Review

9.1 After a journey or activity is completed, the client receives a notification asking them to rate their experience.

9.2 From the Past Tickets tab, the client clicks Leave Review on a completed booking.

9.3 The system displays a review form with rating stars from 1 to 5.

9.4 The client selects a star rating by clicking on the stars. A label appears: 1 star is Poor, 2 stars is Fair, 3 stars is Good, 4 stars is Very Good, 5 stars is Excellent.

9.11 The client receives a notification when their review is published.

9.12 The client can edit or delete their review within 30 days of submission.

9.1 Viewing Reviews

9.13 On any facility or transport detail page, the client can see the average rating displayed as stars with the number of reviews.

9.14 Clicking on the rating opens the reviews section, showing all customer reviews sorted by most recent first.

9.15 Each review shows the reviewer's first name and last initial, rating stars, comment text, date of the journey or activity, and any photos attached.

9.16 The client can filter reviews by rating score using buttons for All, 5 Star, 4 Star, 3 Star, 2 Star, 1 Star.

9.17 The client can sort reviews by Most Recent, Highest Rated, Lowest Rated, or Most Helpful.

PART TEN: LOGOUT AND SESSION MANAGEMENT
10.0 Manual Logout Process

10.1 The client clicks on their avatar in the top right corner of the navigation bar.

10.2 From the dropdown menu, they select the Logout option.

10.3 The system displays a confirmation dialog asking "Are you sure you want to logout?" with Yes, Logout and Cancel buttons.

10.4 The client clicks Yes, Logout.

10.5 The frontend removes the access token from memory and clears any stored authentication state in Redux.

10.6 The frontend sends a logout request to the backend logout endpoint with the refresh token cookie.

10.7 The backend invalidates the refresh token by deleting the session record from the user sessions table.

10.8 The backend also clears the HTTP-only cookie containing the refresh token by setting its expiration to a past date.

10.9 The frontend redirects the client to the homepage with a success message "You have been successfully logged out."

10.10 Any in-progress bookings that had active seat holds are automatically released when the session ends.

10.1 Automatic Logout on Inactivity

10.11 To maintain security, the system implements automatic logout after a period of inactivity.

10.12 The frontend tracks user activity including mouse movements, keyboard presses, clicks, scroll events, and touch events on mobile devices.

10.13 If no activity is detected for thirty minutes, the frontend initiates an automatic logout sequence.

10.14 Before logging out, the system displays a warning dialog asking "Are you still there?" with options Stay Logged In and Logout Now.

10.15 A two-minute countdown timer is displayed on the dialog, showing "Auto-logout in 1:59".

10.16 If the client clicks Stay Logged In or performs any activity, the timer resets, and no logout occurs.

10.17 If the client does not respond within two minutes or clicks Logout Now, the system performs the same logout process as manual logout.

10.18 The system also automatically logs out if the access token expires and the refresh token attempt fails due to the session being invalid.

10.19 This ensures that even if a client forgets to log out on a shared computer, their session will not remain active indefinitely.

10.2 Session Management Across Devices

10.20 The client can be logged into the same account on multiple devices simultaneously, such as desktop computer, laptop, tablet, and mobile phone.

10.21 Each device has its own session record in the user sessions table with unique device information.

10.22 From the Profile Security page, the client can view all active sessions showing device type, browser, operating system, IP address, last activity time, and login time.

10.23 The current session is highlighted with a "This device" badge.

10.24 The client can remotely terminate any session by clicking the Revoke button next to that session entry.

10.25 Upon revoking a session, the backend immediately invalidates that refresh token and any API requests from that device will receive a 401 unauthorized response, forcing a logout on that device.

10.26 The client can also choose to Revoke All Other Sessions, which logs out all devices except the current one.

10.27 This feature is useful if the client suspects unauthorized access to their account or if they lost a device.

10.28 The client receives an email notification whenever a new device logs into their account, showing the device type, location, and time, with a link to revoke the session if it was not them.

10.3 Account Deletion

10.29 From the Profile Security page, the client clicks Delete My Account at the bottom of the page.

10.30 The system displays a warning dialog explaining the consequences of account deletion: all personal data will be permanently removed, booking history will be anonymized but retained for legal compliance, active bookings will be cancelled with applicable refunds according to policy, and the action cannot be undone.

10.31 The client must enter their password to confirm identity and type the word DELETE in a confirmation text field.

10.32 The client checks a box confirming they have downloaded any necessary receipts or tickets before deletion.

10.33 The client clicks Permanently Delete Account.

10.34 The system processes any active bookings by cancelling them and initiating refunds where applicable.

10.35 The system anonymizes the user's personal data in the users table by setting name fields to "Deleted User", email to a unique placeholder, phone to null, and password hash to an invalid value.

10.36 The system sets the account status to deleted and records the deletion timestamp.

10.37 The client is immediately logged out and redirected to the homepage with a confirmation message.

10.38 The client cannot create a new account with the same email address for 90 days as a security measure.
